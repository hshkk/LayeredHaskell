# Risks

### R-1: Modular Parser Design; Technical; Early Development

**Likelihood:** Moderate

**Impact:** High

**Owner:** Leo

Our chosen modular parser design could show to be infeasible for the goals of
our project.

**Mitigate:** We spent several weeks researching design solutions and have tried
to strike a balance between proven methods and experimentation in feature
expressibility.

**Trigger:** Attempting to implement a new feature into the parser, type checker,
or interpreter could be blocked by the modularity architecture.

### R-2: Haskell Knowledge; Team; One Well Experienced Member with Haskell

**Likelihood:** High

**Impact:** Moderate

**Owner:** Hangil

Half of the team is new to Haskell, so there is a learning curve to writing
Haskell code.

**Mitigate:** Hangil has collected learning resources learning Haskell.

**Trigger:** Blocker to appear when needing to write/review Haskell code beyond
the current skill range of a team member.

### R-3: Lack of Time; Business; Unconfirmed

**Likelihood:** Low

**Impact:** High

**Owner:** Oscar

The project has a hard deadline to meet all requirements by the end of Spring
term 2027.

**Mitigate:** We set weekly deadlines each week, and have biweekly meetings with
our project partner to ensure we are on a good pace.

**Trigger:** The remaining work to implement and validate our project's
requirements will take longer than the project deadline.
